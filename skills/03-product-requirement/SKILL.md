# 产品需求管理

## 何时激活

- 用户说"收集需求"、"整理需求"
- 用户说"产品定义"、"写 PRD"
- 用户说"竞品分析"

## 功能列表

### 1. 需求收集

从多个来源收集需求：
- 客户反馈（Redmine）
- 内部建议
- 市场调研

### 2. 产品定义

生成产品需求文档（PRD）：
- 功能描述
- 用户场景
- 技术要求

### 3. 竞品分析

分析竞争对手产品：
- 功能对比
- 优劣势分析
- 差异化建议

---

## 需求收集

### 需求来源

| 来源 | 说明 | 获取方式 |
|------|------|----------|
| Redmine | 客户反馈的功能需求 | API 获取 |
| 邮件 | 客户邮件中的需求 | 手动录入 |
| 会议 | 内部讨论的需求 | 手动录入 |
| 市场 | 市场调研发现的需求 | 手动录入 |

### 需求分类

| 类型 | 说明 |
|------|------|
| 功能需求 | 新增功能 |
| 性能需求 | 性能提升 |
| 兼容需求 | 平台/芯片支持 |
| 文档需求 | 文档完善 |
| 易用性需求 | 使用体验改进 |

### 需求优先级

| 优先级 | 说明 | 评估标准 |
|--------|------|----------|
| P0 | 必须实现 | 影响核心功能或大客户 |
| P1 | 重要 | 多个客户需要 |
| P2 | 一般 | 有价值但不紧急 |
| P3 | 低 | 锦上添花 |

### 输出格式

```markdown
# 需求收集报告

**统计周期**: 2026-01 ~ 2026-02
**需求总数**: 15 条

## 按类型统计

| 类型 | 数量 | 占比 |
|------|------|------|
| 功能需求 | 8 | 53% |
| 性能需求 | 3 | 20% |
| 兼容需求 | 2 | 13% |
| 文档需求 | 2 | 13% |

## 高优先级需求

| ID | 需求 | 来源 | 优先级 |
|----|------|------|--------|
| R001 | I2C DMA 支持 | 客户A | P1 |
| R002 | 低功耗模式优化 | 客户B | P1 |

## 需求详情

### R001: I2C DMA 支持

**来源**: 客户A (Redmine #3003)
**类型**: 功能需求
**优先级**: P1

**描述**:
目前 I2C 只支持轮询模式，希望增加 DMA 传输支持，提高效率。

**价值分析**:
- 提升传输效率 50%+
- 降低 CPU 占用
- 3 个客户有类似需求

**建议**: 纳入 v2.1 版本
```

...

- [性能指标 1]
- [性能指标 2]

- [兼容性要求 1]

## 竞品分析

### 分析维度

| 维度 | 说明 |
|------|------|
| 功能 | 功能完整性对比 |
| 性能 | 性能指标对比 |
| 易用性 | 使用体验对比 |
| 文档 | 文档质量对比 |
| 价格 | 价格策略对比 |
| 支持 | 技术支持对比 |

### 输出格式

```markdown
# 竞品分析报告

## 1. 分析对象

| 产品 | 厂商 | 版本 |
|------|------|------|
| 我方产品 | 本公司 | v2.0 |
| 竞品 A | 厂商A | v3.1 |
| 竞品 B | 厂商B | v2.5 |

## 2. 功能对比

| 功能 | 我方 | 竞品A | 竞品B |
|------|------|-------|-------|
| SPI DMA | ✅ | ✅ | ❌ |
| I2C DMA | ❌ | ✅ | ✅ |
| 低功耗模式 | ✅ | ✅ | ✅ |
| RTOS 支持 | ✅ | ✅ | ❌ |

## 3. 优劣势分析

### 我方优势
- SPI 性能领先
- 文档完善
- 技术支持响应快

### 我方劣势
- I2C 功能不完整
- 芯片支持较少

## 4. 建议

1. 优先补齐 I2C DMA 功能
2. 扩展芯片支持范围
3. 加强性能优化
```
