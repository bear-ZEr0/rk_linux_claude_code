# SDK 发布管理

## 何时激活

- 用户说"发布 SDK"、"准备发布"
- 用户说"审核文档"、"检查发布"
- 用户说"部署环境"

## 功能列表

### 1. 文档审核

发布前检查文档完整性和准确性。

### 2. 发布检查

检查发布包内容和质量。

### 3. 环境部署

自动化部署 SDK 到测试/生产环境。

---

## 文档审核

### 检查清单

| 检查项 | 说明 | 级别 |
|--------|------|------|
| API 文档完整 | 所有公开 API 有文档 | 必须 |
| 示例代码可运行 | 示例代码经过验证 | 必须 |
| 版本号一致 | 文档版本与代码一致 | 必须 |
| 更新日志完整 | CHANGELOG 已更新 | 必须 |
| 拼写检查 | 无明显拼写错误 | 建议 |
| 格式规范 | 格式统一规范 | 建议 |

### 审核流程

1. **自动检查**
   - 文件完整性
   - 版本号一致性
   - 链接有效性

2. **内容审核**
   - API 描述准确性
   - 示例代码正确性
   - 术语一致性

3. **生成报告**
   - 问题列表
   - 修改建议

### 输出格式

```markdown
# 文档审核报告

**SDK 版本**: v2.0.0
**审核日期**: 2026-02-04
**审核状态**: ⚠️ 需要修改

## 检查结果

| 检查项 | 状态 | 说明 |
|--------|------|------|
| API 文档完整 | ✅ 通过 | 所有 API 已文档化 |
| 示例代码可运行 | ⚠️ 警告 | 2 个示例需要更新 |
| 版本号一致 | ✅ 通过 | - |
| 更新日志完整 | ❌ 失败 | CHANGELOG 未更新 |

## 问题详情

### 1. 示例代码需要更新

**文件**: examples/spi_dma.c
**问题**: 使用了已废弃的 API
**建议**: 更新为新 API

### 2. CHANGELOG 未更新

**文件**: CHANGELOG.md
**问题**: 缺少 v2.0.0 版本记录
**建议**: 添加版本更新说明

## 结论

需要修复 2 个问题后才能发布。
```

## 环境部署

### 部署目标

| 环境 | 说明 | 地址 |
|------|------|------|
| 测试环境 | 内部测试 | test.example.com |
| 预发布环境 | 客户试用 | staging.example.com |
| 生产环境 | 正式发布 | release.example.com |

### 部署流程

1. **准备阶段**
   - 检查发布包
   - 备份当前版本

2. **部署阶段**
   - 上传发布包
   - 更新版本信息
   - 更新下载链接

3. **验证阶段**
   - 验证下载链接
   - 验证文件完整性
   - 验证文档访问

### 部署命令

```bash
# 部署到测试环境
/release deploy --env=test

# 部署到生产环境
/release deploy --env=prod
```

## 发布流程

```
1. 代码冻结
   ↓
2. 文档审核 (/release doc-review)
   ↓
3. 发布检查 (/release check)
   ↓
4. 生成发布包 (/release build)
   ↓
5. 部署测试环境 (/release deploy --env=test)
   ↓
6. 验证测试
   ↓
7. 部署生产环境 (/release deploy --env=prod)
   ↓
8. 发布通知
```

## 版权检查脚本

发布前使用以下 Python 脚本检查版权敏感内容，脚本位于 `scripts/` 目录。

### 1. 源代码关键字扫描

扫描源代码文件中的版权敏感关键字（如 `mlp_decode`、`ac3_decode` 等）。

```bash
python3 scripts/check_code.py <目录路径>
```

结果保存到 `./results/result_<timestamp>.txt`。

### 2. PDF 文档关键字扫描

扫描 PDF 文档中的版权敏感关键字（如 `dolby`、`dts-hd`、`杜比` 等），依赖 `pdfgrep`。

```bash
python3 scripts/check_docs.py <目录路径>
```

结果保存到 `results_<timestamp>.txt`。

### 3. Git 历史二进制文件检查

检查 repo manifests 各历史版本中 `libffmpeg*.so` 是否包含敏感字符串，依赖 `git`、`strings`。

```bash
python3 scripts/check_xml.py <manifest文件名> --sdk-dir <SDK根目录>
```

结果保存到 `sensitive_strings_found.txt`。
